## 核心叙事与贡献价值

**你的走位，成为朋友的Boss。先打赢自己，再把挑战交给朋友。**

英文：**Your moves become your friend's boss. Beat it yourself, then send the challenge.**

玩家得到的是自己动作形成的可玩挑战。它不是AI学习出的性格，也不是完整原始轨迹的逐帧还原：Boss模式使用采样、量化后的路线；确定性输入回放是另一项功能。不得宣称首创、全球排名或未观测的用户量。

开发者入口展示三项可检查内容：

1. 固定步进与输入回放：给出真实测试、规则版本及可复现日志；区分原始回放与Boss轨迹压缩。
2. 零运行时JavaScript依赖、规则可改：指向实际规则文件与Node标准库服务；开发工具、可选服务另行说明。
3. 有边界的贡献：移动端触控、损坏/旧版挑战链接、回放一致性和本地化，每个任务附重现步骤与验收条件。单HTML包通过离线验证后，可作为可携带的开发样例。

源码链接放正文或结束页开发者入口。游戏与挑战不以star、转发或拉人解锁；不使用虚构徽章、购买star、投票互助或向其他仓库批量发推广。

## 公开授权后的最小传播实验

**问题：收到朋友的动作Boss后，对方是否真的开玩，并愿意做一个新Boss回应？**

先用3对自愿测试者验证手机链路，覆盖iOS Safari、Android Chrome及他们实际使用的聊天内置浏览器；真实手机从聊天点击，不以桌面模拟器替代。首次分享可作为明确的测试任务，不能叫自然传播。发现任何链接不可达、解码失配、无法触控或无解挑战，先修复再继续。

功能通过后，观察6对双方自愿的真实好友。创作者先玩、生成并自测Boss，再用惯用聊天工具发给对方；接收者只收到正常挑战消息。首轮明确属于受邀试验。之后24小时不催促再试、回发或拉第三人，不给分享/收藏奖励。观察员不代打、不代发。原技术测试中被指导过的人另列，不混入未经指导的首局样本。

| 要记录的阶段 | 真实证据与分母 | 不可替代的指标 |
| --- | --- | --- |
| 制作成功 | 满足门槛并自测通过的人数 / 开始制作的人数 | 点击“生成”不等于可分享Boss |
| 送达 | 双方在自愿实验中确认消息发送/收到 | 分享点击、剪贴板写入、Web Share成功不等于送达 |
| 朋友实际开玩 | 进入挑战并开始模拟的人数 / 已确认收到的人数 | 落地页访问不能替代开玩 |
| 完整尝试与再试 | 输或赢均算一次结束；24小时内再次尝试的人数 / 首次完整尝试人数 | 自动回放和刷新不算再次游玩 |
| 回挑战被玩 | 接收者制作并自测新Boss，原作者实际开始该新Boss的好友对数 / 第一份挑战已被开玩的好友对数 | 创建链接、点分享或说“会试试”不算闭环 |
| 第三人新开玩 | 未被要求转发、首次接触的第三人实际开始人数 | 主持人邀请、脚本和重复设备会话单列 |

只记随机实验ID、挑战ID/父ID、版本、设备类别和阶段；不读取聊天内容或通讯录。暂无全站遥测时用双方自愿确认表；本地浏览器计数不得推算全站用户数。公开URL数据可被编辑，成绩不包装成可信全球榜单。

本实验的内部决策门槛：

- 任何可复现的回放、权限或核心操作问题：暂停传播该版本，继续修复。
- 6位创作者中少于5位独立完成自测与可分享状态：先改创建流程，暂停增加阶段或素材。
- 6位收件人中少于5位真正开玩：先改消息预览、加载或首次操作；不能靠多发消息掩盖失败。
- 实际开玩达到5对、但24小时内没有任何回挑战被原作者玩：此版尚无往返传播证据，检查是否有回应理由；不宣称“上瘾”。
- 至少2对出现真实往返且没有技术退化：值得扩到下一批，并与普通比分挑战比较；6对不足以证明留存、显著优势或爆款。
- 第三人新开玩为0：只获得受邀好友闭环证据。第三人出现也先报告原始人数，不称病毒增长。GitHub stars始终独立读取。

“0/6”“2/5”这样的原始计数比无分母的百分比更有用。设备、版本和24小时观察窗一并保存；无回复属于未知，不自动当作没玩。
